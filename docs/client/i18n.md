# Internationalization (i18n)

The app uses Flutter's official localization system (`flutter_localizations` + ARB files) with `flutter gen-l10n` for type-safe string access.

## Architecture

- **ARB files**: `app/lib/l10n/app_en.arb` (English, template) and `app_es.arb` (Spanish). One file per locale — keys are organized by namespaced prefix within the file.
- **Code generation**: `flutter gen-l10n` produces `AppLocalizations` into `app/lib/l10n/app_localizations*.dart` (imported as `package:ripls/l10n/app_localizations.dart`; the generated files are individually gitignored in `app/.gitignore`). Runs as part of `npm run generate`.
- **Configuration**: `app/l10n.yaml` — sets `nullable-getter: false` so the generated `AppLocalizations` getters return non-nullable types. (Note: this does **not** catch missing translation keys at compile time — `flutter gen-l10n` silently falls back to the template locale and only warns. The CI parity check below is what actually enforces "no missing keys".)
- **Access**: `context.l10n.keyName` via the extension in `app/lib/core/extensions/l10n_extensions.dart`.
- **Locale preference**: `localePreferenceProvider` (Riverpod AsyncNotifier backed by SharedPreferences). `MaterialApp.router` watches this provider for the `locale:` property. Language picker lives in profile settings.
- **Supported locales**: English (en), Spanish (es). System default when no explicit preference is set.

## Key Naming Convention

Keys follow `scopeContextDescription` in lowerCamelCase:

| Prefix | Scope |
|--------|-------|
| `common*` | Shared across screens (OK, Cancel, Save, etc.) |
| `login*`, `register*`, `forgotPassword*` | Auth screens |
| `gear*`, `loan*`, `community*`, `experience*` | Domain screens |
| `discover*`, `discoverFilter*` | Discover screen and filter sheet |
| `portfolio*`, `portfolioDetail*` | Portfolio screens |
| `home*` | Home tab (Needs you / Up next / Yours, calendar) |
| `workshop*` | Workshop (community home) screen and its surfaces (metrics, roster, library, calendar, chooser) |
| `impact*`, `communityMetrics*`, `metricDetail*` | Impact metrics |
| `settings*`, `profile*` | Settings and profile |
| `rpcError*` | Server error messages |

## Best Practices

**Strings belong in ARB files, not Dart code.** Every user-visible string should use `context.l10n.*`. The CI lint check (`npm run lint:dart:i18n`) catches violations.

**The one exception: non-linguistic glyph placeholders.** A placeholder made only of repeated punctuation that conveys a field's *shape* rather than words — `------` in the one-time-code field (`OtpCodeField.placeholder`), for instance — stays a Dart constant. It has no linguistic content and no locale renders it differently, so an ARB key buys nothing and costs something real: when a translatable "6-digit code" string existed alongside the glyph one, the phone and email code fields drifted onto different placeholders (#2925). Keep such a placeholder as a single named constant on the widget that owns it, with a comment saying why it is not a key. This carve-out is narrow — it does **not** extend to abbreviations, units, punctuation-heavy prose, or format examples like `+1 (555) 123-4567`, all of which vary by locale. Note that `npm run lint:dart:i18n` greps a fixed literal allowlist and will not flag either choice, so the comment is what stops the next reader from "fixing" it.

**Every key must exist in every locale.** `npm run lint:dart:l10n-parity` (`scripts/check_l10n_parity.js`) fails if any key in `app_en.arb` is missing from `app_es.arb` or vice-versa. English placeholders are fine when a real translation isn't yet available — the gate is about parity, not translation quality (issue #1972).

**Viewmodels never resolve strings.** Viewmodels expose typed state (enums, error codes, data objects). Widgets resolve to localized text in `build()` via `context.l10n`. This keeps viewmodels testable without a widget tree.

For error state specifically, the canonical shape is `UserError? error` on viewmodel state — see [`app/lib/core/errors/README.md`](../../app/lib/core/errors/README.md) for the typed variants and the `RpcErrorHandler.classify` / `RpcErrorHandler.localize` pair. Viewmodels call `classify(e)` in their `catch`; widgets call `localize(state.error!, context.l10n)` in `build()`.

**Each new string needs both locales.** Add the key to `app_en.arb` (with `@key` metadata) and `app_es.arb` before running `npm run generate`.

**Use ICU message format for plurals and parameters.** ARB supports `{count, plural, =0{...} =1{...} other{...}}` and `{name}` placeholders. Declare placeholders in the `@key` metadata block.

**`static const` lists with display labels cannot use `context.l10n`.** Convert them to local `final` variables inside the method that has `BuildContext` access.

**Test localization.** Widget tests need `localizationsDelegates` and `supportedLocales` on their `MaterialApp` wrapper. See `app/test/helpers/l10n_helpers.dart`. Viewmodel tests (using `ProviderContainer`) need no localization setup.

**Generated code is not checked in.** Run `npm run generate` locally before building, testing, or running the app. CI runs it automatically.
