## Outstanding issues identified during analysis

### 3 still-unanimous-fail combos (all `model_contains`)

After corrections, these 3 cases still fail for all 8 pairs because vision returns an empty Model field — vision is putting the designation into the **title** field instead:

```
breville_bes870                  Vision Model = "" (designation in title)
estwing_builder_framing_hammer   Vision Model = "" (designation in title)
thule_force_xt_xxl               Vision Model = "" (designation in title)
```

This is the next investigation target — either move these assertions to `title_contains` to capture the real signal, or tune `DetectGearInImage` prompt to push more designation text into the Model field. See follow-up section in the plan.

### Threshold notes

The applied thresholds (set ~3pt below observed pass rates from the *uncorrected* run) sit comfortably below the corrected pass rates — none would trip the gate. They are 1–2pt tighter than the rule of thumb and may need a small loosening pass once a real re-run with the corrected suite produces clean numbers.

## Reproducing this snapshot

```bash
go test -tags=benchmark -v -timeout 60m -count=1 \
  -run TestGearImagePrompt ./server/ai/eval/ \
  -anthropic-api-key="$(gcloud secrets versions access latest --secret=anthropic-api-key --project=ripls-dev)" \
  -anthropic-models=claude-haiku-4-5,claude-sonnet-4-6,claude-opus-4-7 \
  -openai-api-key="$(gcloud secrets versions access latest --secret=openai-api-key --project=ripls-dev)" \
  -openai-models=gpt-5.4-nano,gpt-5.4-mini,gpt-5.5 \
  -gemini-project=ripls-dev \
  -gemini-location=global \
  -gemini-models=vertexai/gemini-3.1-flash-lite,vertexai/gemini-3-flash-preview,vertexai/gemini-3.1-pro-preview
```

Numbers will shift slightly because of the post-snapshot ground-truth corrections and the 25 newly-asserted weights / 26 prices.
