### Tie-break logic

**Product wins ties.** However, four categories of engineering concern outrank any marginal product polish item automatically:
1. Security vulnerabilities with a confirmed production-reachable exploit path (no tie-break needed — they are P1 on engineering grounds alone).
2. Server stability risks: no panic recovery → any nil pointer in new streaming code crashes the process.
3. Confirmed CVEs in production code paths (not just theoretical).
4. Velocity-drag patterns (N+1 in hot paths used by core features, e.g., inbox load and community leaderboard).
