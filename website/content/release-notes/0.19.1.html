Release 0.19.1

May 4, 2026

New Features

  • Edit cover photos after creation: Owners can change the cover photo on gear, requests, and experiences after they’ve been created — previously the picker was create-only (#1699)

Bug Fixes

  • Item share sheet showed non-member communities: The share sheet listed every community the gear was already shared into, including ones the current user wasn’t a member of. It now filters to communities you actually belong to and surfaces a typed error when share targets fail to load (#1711)

  • Sharing modal opened from “All Circles” was empty: When the sharing modal was opened from the All Circles view, it didn’t load the user’s communities, so there was nothing to share to. The modal now loads communities on open (#1674)

  • Could invite people to communities you weren’t in: The invite flow let you select non-member communities as the destination, producing invitations the recipient couldn’t act on. Selection is now restricted to communities you belong to (#1666)

  • Inbox last-message previews showed raw @user-id tokens: Previews didn’t decode @-mentions, so they read like @abc123 borrowed your drill instead of the person’s name. Mentions are now decoded in previews (#1668)

  • Sharing system messages duplicated for multi-community gear: When a gear was shared to multiple communities, the system message about the share fanned out into duplicates in chat. Sharing system messages are now deduped (#1679)

  • Inbox rows duplicated for multi-community gear: A gear shared to N communities produced N inbox rows for the same conversation. Inbox now collapses to one row per gear regardless of how many communities it’s shared into (#1680)

  • Gear “shared X ago” rendered the Unix epoch: The “shared X ago” timestamp on gear pages defaulted to 1970 because gear created_at wasn’t populated for older records. It’s now derived from the earliest CommunityGear share (#1669)

  • Community-wide chat messages didn’t push: Posts in the community-wide chat conversation skipped push notifications, so members only saw them by opening the inbox. Push notifications now fire for community-wide chat (#1682)

  • Gear chat blocked members of other shared communities: Chat on a multi-community gear only granted access to members of the gear’s “primary” community. Any member of any community the gear is shared with can now participate (#1675)

  • Manage Members empty state pointed at a non-existent button: The empty state told users to tap an invite button that wasn’t on the screen. Copy is updated and the dead shadow-user-creation path it referenced is removed (#1672)

  • DeleteExperience left RSVPs and time-poll proposals: Cancelling an experience didn’t cascade to participant-state tables, so RSVPs and time-poll proposals kept surfacing on participants’ “my upcoming events” screens. Both tables now cascade-soft-delete with the parent experience (#1698)

  • Deleted users showed as blank rows: Joins to user records that had been deleted produced blank names and avatars. Deleted users now render as a “Former Member” placeholder across all user-joining RPCs and the client UI (#1670)

  • Community preview modal race-seed and swallowed errors: The preview modal had a race where AI-generated content could be overwritten by a stale seed, errors from the streaming RPC were silently swallowed, and several params on the modal were dead code. Modal now seeds correctly, surfaces errors, and the dead params are gone (#1647)

  • UnregisterDevice failed under concurrent delete: Concurrent device-unregister calls could race and one would fail with a not-found error. The RPC is now idempotent — the storage layer wraps ErrRecordNotFound for Update/Delete/UpdateEmbedding so callers can branch cleanly (#1690)

  • Borrow flow used client-derived community IDs: Loading a gear page resolved the community context client-side, which produced inconsistent results when the user’s membership didn’t match the shares. The server is now authoritative for the community ID threaded through borrow (#1705)

Reliability

  • Chat stream timeout raised 15s → 30s: The CI chat stream test hit a 15-second wall on slower runners. Bumped to 30 seconds for CI stability without changing client UX

  • AccessSheet redacts non-member communities: Membership-aware rendering — non-member community names and members are redacted, non-member rows collapse into a single aggregate row, and load errors surface in ManageMembersScreen (#1705)
