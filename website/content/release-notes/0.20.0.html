Release 0.20.0

May 9, 2026

New Features

  • Workshop screen: The fifth tab is redesigned as a community Workshop. It now leads with the roster of active members and four top-level impact metrics (acts, time, savings, CO₂), each tapping into a dedicated detail screen. Nudges surface high-signal moments for follow-up, and after an event completes its recap story includes an inline experience-sampling prompt (“Want to join if they do something like this again?”) so interest signals feed back into the next round of nudges (#1739)

  • Glass modal design: Bottom-sheet modals across the app are migrating to a frosted-glass look — translucent-white surfaces, white-on-glass text, and a frosted scrim. The time and duration pickers, media picker, overflow menu, close-item sheet, danger zone, content info, weekly-goal editor, and cancel-event sheet all render on the new glass foundation in this release. Future creation screens will follow the same primitives (#1798)

  • Image-mode community creation uses the actual image: Previously, selecting an image in community creation uploaded it but then generated from a literal placeholder string, ignoring the image entirely. A new StreamGenCommunityFromMedia RPC sends the image to the AI provider so the generated name and description genuinely reflect what you uploaded (#1648, #1761)

  • Sole-member leave shows an explainer before deleting: When the last member of a community taps Leave, they now see an explainer screen (“You’re the only member — leaving deletes this community for 30 days”) and a standard leave confirmation before the community is soft-deleted. On success, the app navigates to Settings → Communities where the restore countdown is immediately visible (#1720, #1750)

Bug Fixes

  • Gear make/model missing on Details tab: Even when a gear item’s make and model were detected and saved, both fields appeared blank on the Details tab for owners. The fields now display correctly alongside a new Model field in the editing form (#1776)

  • Stats tabs out of order when swiping: Swiping between the Portfolio stats tabs showed them in a different order than the tab bar labels. The swipe order now matches the visual tab order (#1673)

  • Multi-community event and request pages hit permission errors: Event and request detail pages used the same community-scoping bug as gear (fixed in an earlier release): when the active community pin was a community the user wasn’t a member of, every scoped RPC — RSVPs, offers, helpers, sharing — returned permission denied. Both viewmodels now resolve the effective community using the user’s actual membership list (#1752, #1753)

  • Aborted image generation leaked description into next stream: If you switched from image mode to text mode during gear creation, the description from the aborted image stream would appear in the text-mode preview even though the title was correct. Streaming reset now fully clears editedName and editedDescription before each new run (#1758, #1759)

  • Expected server errors reported as fatal crashes: Permission denied, not found, unauthenticated, and similar server-driven codes were classified as unrecoverable by Crashlytics, inflating the fatal-crash dashboard and masking real bugs. These codes are now recorded as non-fatal (#1703, #1779)

Reliability & Safety

  • Daily community purge job: The server now runs a nightly job that hard-deletes communities and memberships whose 30-day restore window has expired — clearing all cascaded rows (gear links, requests, events, conversations, stories, nudges, feed entries) and emitting structured logs per community processed. The job is idempotent and gated by five safeguards (#1620, #1751)

Developer Experience

  • Crashlytics and GCP alerts auto-filed as GitHub issues: Cloud Functions now listen to Crashlytics velocity/regression webhooks and GCP Cloud Monitoring alerts via Pub/Sub and automatically open labelled GitHub issues, with label-based deduplication so the same alert doesn’t open duplicate issues (#1762, #1765, #1782)

  • Secret scanning and rotation runbook: A gitleaks pre-commit hook now blocks commits that contain secrets, auto-installed via npm install. A new runbook in docs/ documents the rotation procedure for every credential the project uses (#1788)

  • Per-PR staging previews for the marketing site: Pull requests that touch website/ now get an automatic staging deploy at a per-branch hostname so changes can be reviewed before merge (#1792)
