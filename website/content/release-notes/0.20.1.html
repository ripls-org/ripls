Release 0.20.1

May 9, 2026

Bug Fixes

  • “Add a time option” silently did nothing in poll vote modal: Tapping “Add a time option” inside a time poll had no effect when the vote modal was opened from most entry points (event joiner, unified time modal, event content view, RSVP modal, inline conversation). The button now correctly opens the propose-a-time modal from every path (#1813, #1818)

  • Calendar export showed raw coordinates instead of street address: Events with a saved location exported to Google Calendar with a raw lat, lng string instead of the human-readable address. Calendar entries now resolve and display the street address; coordinates are only used as a fallback when the address cannot be retrieved (#1763, #1821)

Reliability & Performance

  • Streaming connections were force-closed every 2 minutes: A 120-second WriteTimeout on the HTTP server was terminating every server-streaming RPC (chat, community events) after exactly 2 minutes — roughly 7× faster than the 14-minute stream lifetime the server was designed around. The result was a continuous reconnect storm that inflated server request volume, introduced brief gaps in real-time updates, and wasted Cloud Run billing cycles. The write timeout is now removed; stream handlers cap their own lifetime via the existing 14-minute deadline (#1810, #1819)

  • Feed query cost bounded regardless of concluded-event count: GetFeed was issuing up to 50 database queries when many concluded-event stories appeared in the feed — a regression from the ~17-query baseline. ESM enrichment is now batched: two queries cover all stories regardless of feed size (#1807, #1822)

  • Parallel cache lookups for the same key now share one fetch: Multiple concurrent callers requesting the same uncached item each triggered a separate network fetch. The cache manager now coalesces these into a single in-flight request so only one fetch runs per distinct key (#1814)

  • Gear-from-image detection accuracy improved: The server’s image-based gear detection moved from Anthropic Claude Haiku 4.5 to Google Gemini 3.1 Flash-Lite with a revised prompt, raising the pass rate on a 49-case evaluation suite from 80.9% to 93.6%. All other AI-driven generation tasks (events, requests, communities) were validated against the new model at parity or better (#1777, #1801)

Developer Experience

  • Client-to-server request ID correlation fixed: X-Request-ID headers generated by the Flutter app were not reaching server logs because the h2c upgrade handler bypassed the per-request middleware chain. The middleware ordering is now corrected so every RPC’s client UUID appears in server logs, and context is threaded through the chat and community event broadcasters for per-event log correlation (#1799, #1803)
