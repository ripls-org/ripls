Release 0.22.0


New Features

- Redesigned Workshop: The Workshop tab mirrors the user profile screen structure — community identity block, “known for” topic chips, three impact rows (time shared / money saved / CO₂ avoided), an Available Now rail, and a “Three ways to keep it going” lean-card stack. Community and user profile widgets are now shared so both surfaces stay in sync (#1999, #2010)

- “Known for” detail screen: Tapping a “known for” chip on the Workshop or a user profile opens a category detail screen listing the gear, events, and requests behind it, along with a Top Contributors row on the community surface. Attending an event or helping fulfill a request now earns the chip on your profile — borrowing alone does not (#2031)

- Richer impact equivalences: The Workshop and user profile impact metrics now surface cited, tiered comparisons — time together draws from Holt-Lunstad loneliness research, money saved compares to median paycheck milestones, and CO₂ avoided maps to EPA/EIA daily-life equivalents. Each tier shows a source link and is available in both English and Spanish (#2033)

- Personalized search suggestions: The search panel now shows a top-down layout of Quick Search, Your Communities (avatar carousel), Interests, and Recents. People are now a first-class search result — round avatar, name as title, tap to open their profile. Community and topic browsing stays stationary in the input position; a trailing X replaces the avatar during active search (#2036, #2059)

- Polymorphic share links: All shareable entities — communities, gear, transfers, requests, and events — now produce compact 8-character shortcodes from a single unified table. An event-aware in-app deep-link landing screen handles event shortcodes for logged-in users; the legacy community-invite flow continues to work unchanged during the deprecation window (#2048, #2060)

- Community creation in glass modal: The community creation flow now uses the same frosted-glass surface as gear, event, and request creation. Camera mode bleeds to the sheet edges; text mode uses the standard drag-handle layout. Four previously hardcoded strings are now localized in English and Spanish (#1976, #2047)

Bug Fixes

- “+” button showed location settings dialog after refusal: Tapping the create button after permanently refusing location permission immediately surfaced an “Open Settings” alert before the modal appeared. The alert is now suppressed from the create button; the system permission prompt on a user’s first refusal is preserved (#2002, #2006)

- Couldn’t start a discussion on own gear: The chat conversation was never created at share time, so the chat tab was silent. The conversation is now auto-created on the first visit to the chat tab; repeated opens are idempotent (#2003, #2008)

- Dark theme painted over event offer text boxes: In dark mode, Flutter’s default filled input decoration painted a near-black box over the cream pill used in event offer and need sheets, making text invisible (#2004, #2009)

- Workshop cards and nudges opened old create modal: “Three ways to keep it going” cards, nudge stories, and several other secondary surfaces still routed to the legacy single-type create modals even after unified create launched. All 21 affected call sites now open the unified modal when the flag is on (#2005, #1993, #2007)

- Manage Members invite FAB not working: The “Invite Someone” button on the Manage Members screen was broken after the navigation restructure because it looked up a community that was always null. It now looks up the community by the ID already on the screen (#2000, #2021)

- Invite picker showed a toggle instead of a radio: The community picker in single-select invite mode rendered a switch toggle, implying the row could be deselected. It now shows a decorative radio indicator, and screen readers announce rows as radio buttons (#2001, #2022)

- Could not set location on a newly created event: Event owners were unable to edit the location on events created with a TBD location because an empty string ID was treated as absent. The owner check now runs correctly and the map no longer falls back to Austin (#1991, #2014)

- Request need suggestions hidden by keyboard: On smaller screens, the suggestions strip was obscured by the virtual keyboard when composing a request. Suggestions are now positioned above the keyboard inset (#1992, #1998)

- Location map flashed to Austin then stayed there: The location picker map would sometimes land on Austin instead of the user’s area because GPS coordinates resolved before the Mapbox map fired its creation callback; the pending position is now replayed as soon as the map is ready (#2027, #2028)

- Community avatar flashed to initials on every rebuild: Community avatars in the Workshop carousel and Manage Members list briefly showed the initials placeholder on each parent rebuild. Switching to a Riverpod-cached URL provider eliminates the rebuild cycle (#2044, #2046)

- Android directions app didn’t open: Android 11+ package visibility rules caused canLaunchUrl to return false even when a maps app was installed, producing a “Could not open directions app” toast. The fix adds the required <queries> entries to AndroidManifest.xml and hardens the URL fallback for devices without Google Maps (#1958, #1985)

- Login and invite screens looked bad in dark mode: Auth screen cards used hardcoded Material blue and grey instead of theme-aware colors, leaving them bright and off-brand in dark mode. Cards now use AppColors getters and the Heritage Sage accent (#1965, #1984)

- Small create and feed polish (PR #1998):

  - Camera coaching carousel now leads with event flyers (#1986)
  - Creation modal input now defaults to a capital first letter (#1990)
  - User’s own items now appear in all user-profile views (#1996)

Reliability & Infrastructure

- AI classifier now reads image bytes: Image-mode unified-create classification was previously defaulting to “gear” because the model was asked to classify a photo it never received. Image bytes now flow to the classifier on every provider; 100 % accuracy across 38 test cases (gear, event, request, and ambiguous images) on all three providers (#1939, #2015)

- High-resolution images in URL mode: Pasting a product URL into unified create now retrieves the full-resolution master image instead of the small og:image preview. The extractor checks JSON-LD Product.image first, rewrites e-commerce CDN URL tokens (Amazon, Shopify, Etsy, Target), and picks the largest in-cap srcset candidate as a fallback (#1917, #2035)

- Request inbox N+1 eliminated: ListMyRequests and ListRequests were issuing ~65 database queries per call from per-item conversation enrichment. A new batched helper drops that to ~9; a CI assertion now blocks N+1 regressions at ≤ 12 queries (#1806, #2030)

- Server credentials via file paths: Server API keys and database passwords are now passed via file paths instead of command-line flags, eliminating credential exposure in /proc/<pid>/cmdline and ps output (#1885, #2026)

- Localization parity CI gate: A new CI check fails the build if any English string key is missing from the Spanish ARB or vice-versa. 14 Workshop strings that were untranslated are now available in Spanish (#1972, #2029)
