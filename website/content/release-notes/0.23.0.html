ripls

Release 0.23.0

May 28, 2026

New Features

  • Web app at ripls.app: The full Ripls app is now available in the browser at ripls.app (dev.ripls.app for staging). Non-members can view event details and RSVP directly from a share link without installing the app. Feedback screenshots, video playback, and auth persistence all work on web. Item creation (gallery, text, and URL modes) is enabled; flows that require native hardware surface a clear “not yet supported on web” message (#1195, #2049, #2050, #2155, #2157, #2186)

  • Google Maps: Maps tiles, the location picker, place autocomplete, and geocoding are now powered by Google Maps on all platforms (iOS, Android, and web). The server-side provider interface was extracted so either mapping backend can be selected at deploy time, and both the client picker and the server geocoder can route independently (#2188, #2218, #2224, #2226)

  • Redesigned event and request views: The “Plan” tab is removed from both event and request content views. All information — time, location, needs, RSVP, and impact — lives on a single scrollable tab. A frosted manage-menu sheet (opened via a pencil icon next to the title) replaces the scattered action buttons. RSVPs are now cross-community so the owner’s auto-RSVP appears regardless of which community context you view the event from (#2174, #2177)

  • Revamped Needs & Contributions: Needs and Contributions sheets are rebuilt on the same frosted glass-modal pattern used by location and time polls. Both experience and request scopes share a single widget set under widgets/needs/; scope-specific copy (experience-flavored “chip in / the list” vs. request-flavored “take on a piece / the breakdown”) is handled entirely in locale strings. A Mark Ready / Finalized roster with covered-vs-uncovered callouts and nudge actions for unclaimed needs rounds out the flow (#2160)

  • Time poll UX overhaul: The time-poll flow now mirrors the location-poll flow end-to-end — propose, vote, manage, confirm, and finalized modals with matching chrome. Auto-submit binary voting means a single tap commits your vote immediately. A finalized “It’s Set” card surfaces a calendar-export CTA, and a Choose/Chosen pill on the Event tab’s time row opens the vote modal directly (#2149)

  • Audio support and video fixes: Muted background videos no longer hijack other apps’ audio on iOS (Spotify, podcasts keep playing). Content views and the media carousel both get a mute/unmute toggle. Video uploads now surface the server-returned URL instead of a local picker path, fixing the blank background regression. Non-owner community members can now add media to events, requests, and gear they don’t own (#2092)

  • Candidate media thumbnails: The “Replace background” modal for URL-mode and Pexels-mode unified-create now offers 3–4 squircle candidate images (and video candidates) to swap in with a single tap. Attribution-preserving import flows through the trusted stock-provider path so Unsplash credit is never lost (#2038, #2062, #2063, #2085)

  • Server-side localization: Push notifications, emails, chat system messages, and user-visible RPC error messages are now rendered in the recipient’s preferred language. AI prompts pass the recipient locale so suggestions and descriptions come back in the right language. CI gates enforce catalog parity and block inline string regressions (#1904, #2153)

  • RSVP to in-progress events: Users can now RSVP to an event that has already started, rather than being blocked at the door (#1080)

  • Manual entry in unified create: A pencil-and-paper icon on the right edge of the Generate button lets users skip AI generation entirely and author items manually (#2178)

Bug Fixes

  • Borrow queue duplicates: Tapping “Borrow” quickly twice no longer queues the same user twice. The server now enforces a uniqueness check and the client suspends the button during the in-flight request (#2116, #2121)

  • Missed notifications for new requests and event offers: Push dispatch for community events was silently dropping deliveries. Instrumentation added across the dispatch path exposed the gaps; the fan-out branches now log outcomes and the missing triggers are wired correctly (#2109)

  • Duplicate scheduled event notifications: The day-before reminder was firing multiple times for the same event. The scheduler now deduplicates notification records before dispatching (#2089)

  • Photos in event chat via media bar: Uploading a photo to an event conversation via the “+” on the media bar no longer spins indefinitely and then denies access. The GetMedia access rule now includes loan/transfer participants, and navigating back no longer triggers a spurious permission error (#1110, #2170)

  • Completed gives no longer listed in inventory: Gear that has been fully given away is now excluded from the user’s gear inventory so it no longer appears as still “Giving” (#1051, #2103)

  • DeleteGear left dangling transfer rows: Deleting gear left associated transfer rows in a CANCELLED-but-live state, causing non-owners to hit a 404 on GetGear. Transfer-bound RPCs now use a lenient read that tolerates the soft-deleted gear state (#1701, #2184)

  • GetExperience permission denied for event creator: Event owners were seeing permission_denied when fetching their own events from the public experience RPCs. The ownership check now correctly grants access to the creator regardless of how the experience is fetched (#1916)

  • AI gear description was verbose: Image-mode unified create was producing multi-sentence descriptions with marketing copy and spec narration instead of a single identifying sentence. The prompt now requires one crisp sentence (~80–160 chars) naming the item and its primary use (#2225, #2226)

Security

  • GetUser PII scoping: Email address and home-location ID are now returned only when the caller is fetching their own profile (#2138, #2167)

  • GetNearbyUsers/GetNearbyGear community scoping: Exact home coordinates are no longer disclosed to arbitrary authenticated callers. Results are now community-scoped and coordinates are quantized before leaving the server (#2137, #2144)

  • Cross-community event/gear/request data leak: Experience, gear, and request RPCs now enforce community-scoped read access so data from one community cannot be read through another community’s membership (#2136, #2143)

  • SSRF hardening: A shared safehttp package now guards all URL-mode RPCs that fetch user-controlled URLs. Internal cloud metadata endpoints, RFC1918 addresses, and loopback services are blocked before the request leaves the server (#2135, #2140)

  • Chat access after community leave: Leaving a community now strips the leaver from ChatConversation.ParticipantIds, preventing ex-members from reading or sending messages in community conversations (#2133, #2141)

  • SendMessage authorization: ChatService.SendMessage now routes through requireConversationAccess, closing the gap where conversation participants and community membership were not verified before accepting a message (#2132, #2139)

  • SetCommunityRegionOverride access control: The RPC is now gated on the caller being both the current owner and an active member, preventing former owners from modifying community regions after leaving (#2134, #2142)

Reliability & Infrastructure

  • Community impact metrics performance: GetCommunityImpactMetrics was taking 10+ seconds per call due to per-item database queries. Per-request memoization and batched percentile queries bring it down to under a second (#2055, #2070)

  • Image upload sanitization: The upload path now validates content types against an allow-list, enforces unified size caps, rejects decompression-bomb dimensions, and transcodes non-web image formats (HEIC, TIFF, BMP) for browser compatibility. EXIF metadata stripping is available as an opt-in (#1953, #2191)

  • AI streaming rate limiting: Per-user rate limits are now enforced on AI streaming generation RPCs and the AddMediaFromURL generic-URL path. Dev mode runs all rules in metrics-only shadow mode so limits can be tuned before enforcement (#2066, #2098, #2100)

  • Chat notification N+1 eliminated: Gear, experience, and community name lookups in the chat-notification fan-out were issued per message. They are now batched ahead of the fan-out loop, cutting the query count proportionally to the number of chat participants (#2173, #2189)

  • Dead leaderboard code removed: The community leaderboard shipped fabricated data for every community and was never user-visible. All server and client leaderboard code has been removed (#1354, #2102, #2180)

  • Blocking Go format CI check: The Go format gate is now blocking in CI, preventing gofmt violations from landing on main (#2190)
