Release 0.23.2


Bug Fixes

- Android location search broken in production: Google Maps place autocomplete returned an empty, flickering dropdown on Android in prod (iOS and web worked fine; the map itself rendered correctly). The root cause was that the X-Android-Cert header was sent as a colon-separated uppercase hex SHA-1 fingerprint (the form keytool and Play Console display), but the Places API (New) requires it as a bare lowercase hex string — the mismatch produced a 403 API_KEY_ANDROID_APP_BLOCKED response even though the fingerprint was on the allow-list. As a follow-up, the per-platform app-restricted map-SDK keys were decoupled from Places/Geocoding REST calls: a new dedicated API-restricted (not app-restricted) key now serves all platforms for autocomplete and geocoding, removing the fragile platform-header mechanism entirely. A $100/month budget tripwire and daily quota caps (25 000/day) on autocomplete, place details, and geocoding were applied in production as an abuse backstop (#2246, #2247)
