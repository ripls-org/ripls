Release 0.28.2

July 31, 2026

Nudge notification delivery, locale-aware in-app copy across four surfaces, and enum storage correctness.

Bug Fixes

  • Nudge Notifications Not Delivering: Three nudge RPCs — poll voter nudges and uncovered-need claimers — were comparing RSVP intention against the fully-prefixed enum name ("RSVP_INTENTION_YES") while every writer stores the bare value ("YES"). The mismatch caused all three nudges to match zero recipients and send no notifications for as long as the code existed. Fixed and covered by a test that fails against the old comparison (#2820)

  • In-App Copy Now Locale-Aware: Four UI surfaces were rendering server-composed English strings regardless of the device locale. All four now derive their labels client-side from typed proto fields and format in the viewer’s locale via intl:

    • Needs-you queue — decision reason, due date, and message preview from typed HomeDecisionReason enum and due_at_unix_sec (#2827, #2836)
    • Experience chat time params — scheduled-time changes now send a structured instant + timezone offset; clients render via DateFormat in the viewer’s locale; a latent bug where system-message updates dropped templateKey/templateParams (causing stale templates to re-render) is also fixed (#2837)
    • Impact metric detail — source breakdown and recent-activity labels now use the typed ImpactSourceType enum; a live string-matching contract (_sourceOrder = ['Loans', 'Giveaways', …]) that would have silently broken screen ordering on a label rename is replaced with enum-keyed aggregation (#2838)
    • Plans-tab calendar — role lines, obligation titles, and time labels now render from typed status enum and raw timestamps with ICU plurals for attendance counts (#2839)

  • Enum Columns Stored as INTEGER: The protosql layer was creating enum flat columns as TEXT and populating them with decimal digit strings ("1" instead of 1). This caused integer-literal comparisons in queries to fail (PostgreSQL error 42883) and made any ordering lexicographic rather than numeric. An idempotent migrateEnumColumnsToInteger step converts legacy TEXT columns at startup; rolling deploys are safe in both directions (#2840)

Internal

  • SQL Construction Safety: All SQL identifiers now flow through a validating quoteIdent helper; check-sql, a new CI gate, catches raw identifier splices that gosec cannot see through interface indirection. LIKE metacharacters in search terms are escaped (previously % matched all rows), and caller-supplied LIMIT values are clamped. A dotted-path quoting bug that had silently prevented stock_image embeddings from ever backfilling is also fixed (#2795)

  • Dart Analyzer Strictness: strict-casts, strict-raw-types, and 22 SDK lint rules enabled across 833 non-generated Dart files. A real defect found during the sweep: expressInterest was throwing bare Strings instead of classified UserErrors, destroying stack traces (#2794)

  • Proto Wire-Breaking Gate: buf breaking is now wired into CI at WIRE level, catching field-number reuse and type changes. Proto deprecation policy (two-release wait for API fields, same-release removal for models) is documented in docs/proto_conventions.md (#2828)

  • RSVP Enums and Tech-Debt Cleanup: ExperienceRSVP.intention/attended migrated from strings to enums with an idempotent boot backfill; legacy portfolio inbox (six RPCs with no callers) deleted; deprecated entity-card fields from #2012 removed; goconst enabled at zero findings after fixing the three underlying defects it was pointing at (#2829, #2820, #2020)

  • Lint Ratchet: funlen, cyclop, and dupl thresholds tightened after refactoring fetchAll (671 → ~50 lines per section) and generateFeedItems; query-count guards added to the portfolio and feed hot paths to catch N+1 regressions without changing response bytes; InboxItem model deleted (was a two-field wrapper; fields moved directly onto ConversationState) (#2816, #2814)
