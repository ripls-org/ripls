Release 0.30.0


Adaptive desktop layouts, a calendar fix for landscape viewports, a request-writer race fix, and registration hardening.

New Features

- Ripls Works on Desktop: The web app now reads as designed at any viewport width, not as a phone layout stretched sideways. Width caps keep every content surface inside a comfortable reading column on wide screens, bottom sheets are centered and width-capped, and the Plans calendar switches to a two-pane grid-beside-detail layout at expanded widths. The changes are constraint-first: on phone-shaped viewports the layout is pixel-identical to before (#2912)

Bug Fixes

- Calendar Now Usable in Landscape: The month grid sized itself from width alone, so at landscape browser aspect ratios (roughly 1.1:1 width-to-height and wider) it consumed the entire viewport, hid the day-detail panel, and left no way to scroll back — the calendar was effectively gone. The grid now derives its cell size from both axes and takes the smaller, so it fits any viewport and stays readable. Also fixed the same sizing bug in the shared calendar and workshop calendar panels (#2908)

- Cancelled Requests No Longer Resurrect: A race between SubmitRequest’s async writers (suggestion chips, stock imagery) and a concurrent CancelRequest or UpdateRequest could silently revert the user’s change. Each goroutine read a stale snapshot and wrote it back whole, overwriting whatever happened in between. The fix wraps each async write in a serialized database transaction with a row lock so concurrent mutations are never lost (#2900)

- Community Lifecycle Events Handled in Client: When a community was deleted, renamed, had ownership transferred, or a member rejoined within the grace window while the app was open, the realtime event hit an unhandled path in the client router and was silently dropped. All five community-lifecycle event types are now routed and cause the affected views to refresh their data (#2869)

Internal

- Registration Requires Email Verification: EmailRegister no longer accepts a password field — a mailed one-time code is required to create an account in all environments. The set of accounts that hold a password hash can only shrink from here; existing password sign-ins continue to work (#2864)

- Deprecated Per-Community Stream Removed: The StreamCommunityEvents RPC deprecated in v0.29.1 is deleted. All clients on v0.29.1 or later use the per-user StreamUserEvents instead, and adoption has turned over (#2869)

- Flutter 3.47.0: Updated the Flutter SDK from 3.44.8 to 3.47.0 (#2883)
